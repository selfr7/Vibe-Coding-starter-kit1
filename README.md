# Vibe Coding Starter Kit V1.0版本

这是一个面向 AI Vibe Coding 新手的项目模板。

它的目标不是让你先学会完整的软件开发，而是提前建立一个清晰、可重复、相对安全的 AI 开发工作环境。

模板的设计逻辑只有一句话：**你负责说想法、做决定；AI 负责读文档、跑命令、干所有技术活。**

所以这份 README 刻意很短。你不需要学会任何终端命令——所有需要执行的命令都写在给 AI 的提示词里，复制、粘贴、照它说的做就行。

## 适合谁？

* 想用 Claude Code、Codex、Cursor、Windsurf 等 AI Coding Agent 做项目的人
* 会描述需求，但代码基础有限的人
* 想快速做网站、工具、SaaS、MVP 的个人开发者
* 希望多个项目都使用同一套开发规则的人

## 你只需要做三件事

1. **复制这个文件夹**，改成你的项目名（不要直接在模板里做正式项目）
2. **用你平时的 AI 编程工具打开这个文件夹**，进入对话
3. **把下面这段「第一次启动」提示词发给 AI**，然后照它说的做

## 第一次启动：把这段发给 AI

> 我是新手，这个项目是用模板创建的。请按顺序做：
>
> 1. 阅读 README.md、AGENTS.md 和 docs/ 下的所有文档
> 2. 检查我的电脑环境：Node.js 装了没有、项目依赖装了没有。缺什么就一步一步带我装好，每一步告诉我点哪里、输什么
> 3. 启动项目，让我在浏览器里看到「🎉 跑起来了！」的页面，然后停下来等我确认
> 4. 我确认后，开始采访我，帮我把 docs/PROJECT.md 填好，整理好给我确认后再写入文件
>
> 全程用大白话解释你在做什么。

之后会发生什么：AI 可能带你装一两个基础软件（都是点下一步的事），然后你会看到项目页面。**整个过程你不需要自己敲任何命令。**

⚠️ 唯一要记住的事：**不要直接双击 index.html 打开**。那只会看到一个「启动失败」提示页——页面必须由 AI 启动项目后，在浏览器访问它给出的网址。

## 模板结构

```text
vibe-coding-starter/
├── README.md                 # 给人看的使用说明（从这开始）
├── AGENTS.md                 # 给 AI 的项目规则（最重要）
├── CLAUDE.md                 # 让 Claude Code 也能自动读到规则
├── LICENSE                   # 模板本身的开源许可
├── ASSET_LICENSE.md          # 图片、字体、Icon、Logo 等授权记录
├── package.json              # 项目依赖和命令
├── .env.example              # 环境变量清单（密钥的"占位模板"）
├── index.html                # 网页入口
├── vite.config.js 等三个配置  # 构建配置，交给 AI，不用管
│
├── docs/
│   ├── PROJECT.md            # 项目说明书：做什么、不做什么（AI 会采访你帮你填）
│   ├── PROJECT.example.md    # 填好的示例，填不出来时照着找感觉
│   ├── DESIGN.md             # 视觉与 UI 设计规则
│   ├── AI_WORKFLOW.md        # 推荐工作流 + 提示词库（含急救提示词）
│   ├── DEPLOY.md             # 打包与上线
│   └── CHANGELOG.md          # 开发日志：AI 每次改了什么
│
├── src/                      # 源代码（AI 主要在这里干活）
│   ├── App.jsx               # 首页（现在是占位页，让 AI 替换）
│   ├── main.jsx              # 程序入口，一般不动
│   ├── index.css             # 全局样式
│   ├── components/           # 页面组件
│   └── lib/                  # 工具函数
│
├── public/                   # 图片、字体、图标等静态资源
│
└── scripts/
    └── ip-audit.md           # 上线前 IP/素材检查清单
```

> 树里没列出来的：`node_modules/`（依赖包）、`package-lock.json`（版本锁定）、`dist/`（构建产物）都是自动生成的；`.gitkeep` 是空文件夹的占位标记。这些都不用管，也别手动改。

## 日常怎么用

- **每次开工**，先发这句，让 AI 自己接上上下文：

> 这是继续开发的项目。请先阅读 README.md、AGENTS.md、docs/ 下的文档和 docs/CHANGELOG.md 的最近几条，总结项目当前状态；然后启动项目让我看到页面；完成后等我指令。

- **想加功能、改样式、改文案**：直接用大白话说。AI 会先给计划、你确认后再动手（这是 AGENTS.md 里定好的规矩）
- **设计没想法**：说一句「帮我把 docs/DESIGN.md 填好，先给我提案」
- **大改动之前**：说一句「先把当前能正常用的状态提交保存，再开始改」
- **改崩了、跑不起来了**：打开 `docs/AI_WORKFLOW.md` 里的「急救提示词」，把对应那句发给 AI

## 素材规则

任何图片、字体、Icon、Logo 或第三方资源，在不确定来源/授权时，不要直接用于商业项目。

优先顺序：

1. 自己制作
2. AI 生成并根据所用 AI 服务条款确认可用性
3. 有明确商业授权的素材
4. 明确许可的开源资源
5. 其他来源（必须先核实授权）

把使用的第三方资源记录到 `ASSET_LICENSE.md`（这项也是 AI 在每次使用素材时更新的）。

## 打包与上线

这一版模板面向「做出来自己用 + 最多分享个公开网址」，两件事都让 AI 代劳，详见 `docs/DEPLOY.md`：

- **打包**：把项目变成一个可以双击打开、可以压缩发给朋友的文件夹——把 DEPLOY.md 里「打包」那段提示词发给 AI 即可
- **上线**：把项目变成一个公开网址。这一步情况和选择都比较多，模板不写死步骤——把 DEPLOY.md 里「上线」那段提示词发给 AI，让它按你的情况带你做

## 安全提醒

不要把 API Key、数据库密码、Token 等写进源代码。

* 真实密钥放在 `.env.local`（已被 .gitignore 忽略，不会被上传）
* 需要密钥时直接告诉 AI「帮我创建 .env.local，我要填 XX 的密钥」，它会带你完成

## 想做别的类型的项目？

模板默认内置的是网页项目骨架（适合网站、工具、SaaS）。如果你想做浏览器插件、小程序、桌面应用等，直接告诉 AI：

> 这个项目想做的是 XX，请把技术栈换成合适的方案。先给我计划和新旧结构的对比，我确认后再动手。

## 关于这个模板

这是一个起点，不是法律意见，也不是完整的企业级安全/合规方案。

商业项目上线前，如果涉及重要品牌、较大商业规模、敏感数据或复杂第三方授权，应该进行更专业的法律和安全审查。
